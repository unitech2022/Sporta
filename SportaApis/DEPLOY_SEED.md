# نشر السيرفر — المايجريشن + البيانات التجريبية

دليل مختصر لتطبيق تعديلات قاعدة البيانات وتعبئة بيانات التجربة بعد رفع الملفات.

---

## ٠) رمز التحقق عبر واتساب (Authentica) — مطلوب قبل التشغيل

الدخول والتسجيل في التطبيق صارا برمز واتساب لا بكلمة سر. المفتاح سرّ ولا يُكتب
في `appsettings.json`، بل في متغيّر بيئة:

```bash
export Otp__Authentica__ApiKey='<مفتاح Authentica>'
```

**السيرفر يرفض الإقلاع خارج بيئة التطوير بلا هذا المفتاح** — عمداً: بدونه يسقط
النظام إلى المزوّد المحلي الذي يطبع الرمز في اللوق، أي أن كل من يقرأ اللوق يدخل
أي حساب.

أرقام الاختبار (حساب مراجع App Store وحسابات العرض) لا تُرسَل لها رسالة ولها
رموز ثابتة، وتُضبط بمتغيّرات بيئة مستقلة:

```bash
export Otp__TestNumbers__0500000301='123456'
```

لا تُدرج في هذه القائمة رقم مستخدم حقيقي أبداً — كل رقم فيها باب خلفي كامل لحسابه.

بقية إعدادات القسم (`Otp:ResendCooldownSeconds`، `MaxSendsPerHour`، القناة
الاحتياطية `FallbackMethod`) في `appsettings.json` وتكفي قيمها الافتراضية.

**ملاحظة على الحسابات القائمة:** لا تحتاج ترحيلاً — كلمات سرها تبقى في القاعدة
لكنها معطّلة، ويدخل أصحابها برمز واتساب على أرقامهم نفسها. الدخول بكلمة سر بقي
لحسابات الأدمن والموظفين وحدها (لوحة التحكم).

## ١) تعديلات قاعدة البيانات (تُطبَّق يدوياً)

تعديلان هذه الجلسة:
- **عمود `Status` على جدول `WalletTransactions`** (يميّز عمليات الدفع الناجحة
  عن الفاشلة).
- **`AddOtpPurposeAndVerificationToken`** — أعمدة الغرض والتذكرة على جدول
  `OtpCodes` (إضافية بالكامل، لا تمسّ بيانات قائمة).

المايجريشن **لا يُطبَّق تلقائياً** — طبّقه بإحدى طريقتين قبل تشغيل السيرفر:

**الطريقة أ — أمر EF (موصى به، يحفظ سجل المايجريشن):**
```bash
cd SportaApis
dotnet ef database update
```

**الطريقة ب — SQL خام مباشرة على القاعدة:**
```sql
ALTER TABLE `WalletTransactions`
  ADD COLUMN `Status` int NOT NULL DEFAULT 0;

-- سجِّل المايجريشن حتى لا يعيد EF تطبيقه لاحقاً:
INSERT INTO `__EFMigrationsHistory` (`MigrationId`, `ProductVersion`)
VALUES ('20260715193327_AddWalletTransactionStatus', '9.0.15');
```

`Status = 0` تعني "ناجحة"، فكل الصفوف الموجودة تبقى ناجحة تلقائياً. لا فهرس ولا
مفتاح خارجي — إضافة عمود فقط، غير هدّامة.

> **مهم:** طبّق المايجريشن **قبل** تشغيل السيرفر بعلم التعبئة، وإلا تفشل البذور
> على عمود مفقود.

### إعدادات جديدة (تُنشأ تلقائياً مع البذور، لا تحتاج SQL)
ستة مفاتيح في `SystemSettings` تُدار من لوحة التحكم، تُبذر تلقائياً في مسار
التعبئة: `wallet_topup_min` (10)، `wallet_topup_max` (5000)،
`wallet_topup_fee_percent` (0)، `wallet_topup_fee_fixed` (0)،
`wallet_topup_fee_vat_percent` (15)، `wallet_topup_notes`.

## ٢) تعبئة البيانات التجريبية (تشتغل في أي بيئة)

البذور كانت مقيّدة ببيئة `Development`. الآن تشتغل أيضاً في **أي بيئة** إذا فُعِّل
مفتاح إعدادات — فتقدر تعبّئ سيرفر Production دون تحويله إلى Development.

**الخطوات:**
1. طبّق المايجريشن (القسم أعلاه).
2. فعّل المفتاح — أضف في `appsettings.json` على السيرفر:
   ```json
   "Seeding": { "Enabled": true }
   ```
   أو مرّره كمتغيّر بيئة: `Seeding__Enabled=true`.
3. شغّل السيرفر مرة واحدة — تُنشأ البيانات كلها.
4. **أطفِ المفتاح** (`false`) بعد التعبئة. (البذور idempotent فتركه مفعّلاً آمن،
   لكن إطفاؤه أنظف.)

### ما الذي يُنشأ
ملاعب، نادٍ ومالكه، مدربون، لاعبون بمحافظ، مباريات (مفتوحة/مكتملة)، أمريكانو،
بطولات، حجوزات بكل حالاتها (مكتمل/مؤكد/معلّق/ملغى)، وجلسات تدريب مُقيّمة.
كل بذرة idempotent — تتخطى إذا كانت بياناتها موجودة، فما تتكرر.

## ٣) حسابات التجربة

تسجيل الدخول **بالجوّال** (لا الإيميل). كل الحسابات جاهزة بعد التعبئة:

| الدور | الجوّال | كلمة المرور | الاسم |
|---|---|---|---|
| **لاعب** | `0500000201` | `Demo1234` | عبدالله القحطاني |
| **مدرب** | `0500000101` | `Coach1234` | محمد أحمد |
| **مالك ملعب** | `0500000301` | `Demo1234` | سلطان الراشد |
| مدير (لوحة التحكم) | `0500000000` | `Admin1234` | مدير النظام |

> ⚠️ **انتبه لكلمة مرور المدرب:** `Coach1234` **وليست** `Demo1234` — لأن بذرة
> المدربين القديمة تنشئه أولاً. بقية اللاعبين وملاك الملاعب على `Demo1234`.

لاعبون إضافيون للتجربة: `0500000202` … `0500000208` (كلمة المرور `Demo1234`).
مدربان إضافيان: `0500000102`، `0500000103` (كلمة المرور `Coach1234`).

---

تم التحقق من كل ما سبق فعلياً على قاعدة نظيفة ببيئة **Production + المفتاح**:
البذور اشتغلت، الحسابات الثلاثة سجّلت دخول، والحجوزات أُنشئت بأسعار وعمولات صحيحة.
